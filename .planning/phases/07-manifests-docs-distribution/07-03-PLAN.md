## apply_patch contract (fixed here)

Grammar (codex-rs/apply-patch/src/parser.rs, quoted in 07-RESEARCH Pattern 8): a hunk header is a
line that starts, at column 0, with `*** Add File: `, `*** Update File: `, `*** Delete File: ` or, inside
an update hunk, `*** Move to: `, followed by the path and a line feed. Added lines start with `+`, so a
header-looking text inside added content is never a header.

- `main()`: a new branch `elif tool == "apply_patch":` reading `tool_input.get("command")`; when it is a
  non-empty string, `hit = patch_hit(command, cwd)`; no note is appended (this is not the Bash
  heuristic). WRITE_TOOLS, the Bash branch, MESSAGE, the deny JSON shape and the module-level fail-open
  `except Exception` stay as they are.
- `patch_hit(text, cwd)`: for each line of `text.splitlines()` starting with one of the four prefixes,
  the path is the rest of the line with surrounding whitespace (and a trailing carriage return)
  removed; an empty path is skipped; the first `JUDGED` budget (reuse MAX_JUDGED) paths go through
  `sources_target(path, cwd)`, later ones through `visible_sources(path)`; the first hit is returned,
  else None. Linear in the patch size. Docstring names D-05 and Pattern 8.
