<objective>
Complete the nine error classes with the two filesystem-shaped checks — a `.claude/` folder
below the root (E8) and a rendered deliverable with no source beside it (E9) — then turn the
fixture set into the thing the ROADMAP's second criterion actually asks for: nine trees, each
carrying exactly one violation, each asserted both for the identifier that must fire and for
the ten that must not.

Purpose: the negative half is the whole point. Every error fixture exits 1 for *any* error, so
a suite that asserts only the exit code passes just as happily against a linter that reports one
class on all nine trees. The isolation sweep is what makes criterion 2 mean what it says.
Output: `E1`…`E9` complete, a generator with a stated contract, and a test loop that cannot be
satisfied by a broken linter.
</objective>

## Why the error fixtures are generated and not committed

D-29, restated so the executor does not "improve" it back: the `e8` fixture needs a nested
`.claude/` directory and this repository's `.gitignore` ignores `.claude/` at any depth, so
that fixture literally **cannot** be committed; per-class isolation is what lets the suite
assert "no other identifier fires", which a single mega-fixture would hide; and the pattern
already exists in the harness as `tests/fixtures/make-adopt-fixture.sh`, which this generator
mirrors and never modifies. Flipping to committed trees would mean re-solving the ignore
problem and rewriting the isolation assertions — rated **costly** in `02-CONTEXT.md`.
