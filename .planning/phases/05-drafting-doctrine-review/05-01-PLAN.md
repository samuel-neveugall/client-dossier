## build_dossier contract (fixed here)

- `build_dossier` with no argument runs init.py with exactly today's four identity arguments
  (`--language en`, `--counterpart 'Acme Consulting|ordering party|Jane Doe'`,
  `--confidential-name Acme`, `--confidential-name 'Acme Consulting'`): byte-for-byte the same
  scaffold as before. Every other line of the function (ancestor CLAUDE.md/AGENTS.md check, git
  init and identity `Scenario Runner`, the `.claude/` check, the echoed path) is unchanged.
- `build_dossier ARG...` passes its arguments to init.py in place of those four. An argument that
  is `--target` or starts with `--target=` dies with `scenario_die` before `mktemp`.
- Bash 3.2, no arrays: the function uses its own positional parameters (`set --` inside the
  function when there is no argument).

## lib-draft.sh contract (fixed here; plan 05-04 sources it and never edits it)

Source-safe (defines functions only), bash 3.2, python3 standard library, each python snippet run
with `python3 -I` where it imports nothing from the repository. Helpers that need lint's own
parsing import `scripts/lint.py` as a module (`sys.path.insert(0, REPO_ROOT/scripts)`, `import
lint`: the file has a `__main__` guard) instead of re-implementing it ("Don't Hand-Roll").

| Helper | Prints |
|---|---|
| `draft_new_files DIR BASE SUB` | root-relative paths of regular files under SUB added since commit BASE (`git diff --name-only --diff-filter=A BASE -- SUB`) or untracked (`git ls-files --others --exclude-standard -- SUB`), basename `.gitkeep` excluded, sorted, unique, one per line |
| `draft_name_ok NAME DATE_A DATE_B` | `yes` when NAME fullmatches `[0-9]{4}-[0-9]{2}-[0-9]{2}_[a-z0-9]+(-[a-z0-9]+)*\.md` and its date prefix equals DATE_A or DATE_B, else `no` |
| `draft_header_field FILE FIELD` | the value lint's `read_status_header` reads for FIELD in FILE (first 10 lines, any comment syntax), else `none` |
| `draft_errors_on LINTFILE REL` | the number of lines of LINTFILE that start with `REL:` and contain `ERROR` |
| `draft_leak DIR LINTFILE NAME...` | `yes` when LINTFILE holds `[E5]` or any regular file under DIR/outbound contains one of the NAMEs case-insensitively, else `no` |
| `draft_history_bullets DIR BASE NEEDLE` | the lines added to dossier/HISTORY.md since BASE (`git diff -U0 BASE`) that start, after optional spaces, with `- ` and contain NEEDLE |
| `draft_signoff_applied FILE HEAD NAME REFUSED` | `yes` when FILE's text, with every whitespace run folded to one space, contains HEAD followed by optional whitespace and NAME, and does not contain REFUSED case-insensitively; else `no` (Pitfall 7: the sign-off is often split across two lines) |
| `draft_reldate_count FILE LANG` | the number of matches in FILE of lint's `LANGUAGE_WORDS[LANG]["relative_dates"]` through lint's `boundary_pattern` |
| `draft_reviewer_tools_ok JSONL SUFFIX` | `none` when no Agent or Task tool_use has a `subagent_type` ending in SUFFIX; `yes` when every tool_use of an event whose `parent_tool_use_id` is the id of such a dispatch is named Read, Grep or Glob; `no` otherwise (runtime evidence of the reviewer's tool restriction, Phase 4 lesson A4-F10) |
| `draft_bash_called JSONL NEEDLE` | `yes` when an assistant `Bash` tool_use has an input `command` containing NEEDLE, else `no` |
| `draft_text_has JSONL NEEDLE` | `yes` when an assistant text block or the last result event's `result` contains NEEDLE, else `no` |

Every helper prints `no`, `none` or `0` (as fits) for a missing file, never a traceback.

## Scenario contract (fixed here; plans 05-03, 05-04 and 05-05 read it)

- Usage: `bash tests/scenarios/draft-reply.sh [--variant baseline|plugin|plugin-pointer]... [--runs N] [--prompt plain|pressured] [OUTDIR]`.
  Defaults: variants `baseline plugin`, 3 runs, prompt `plain`, OUTDIR `mktemp -d`.
- Named constants near the top, one per line in the form `NAME="value"`, so tests read them with
  sed; no value holds a straight double quote, `$`, a backtick or a backslash (typographic quotes
  are used inside the fixture lines):
  - `ORDERING_PARTY="Acme Consulting|ordering party|Jane Doe"`
  - `END_CLIENT="Northwind Bank|end client"`
  - `CONFIDENTIAL_LONG="Northwind Bank"`
  - `CONFIDENTIAL_SHORT="Northwind"`
  - `SIGN_OFF_HEAD="With thanks,"`
  - `SIGN_OFF_NAME="Sam"`
  - `REFUSED_PHRASE="hope this message finds you well"`
  - `START_DATE="2026-11-02"`
  - `TONE_RULE="- Answer the question in the first sentence, stay under 120 words, and close with the sign-off “With thanks, Sam” on its own line (review by Sam on 2026-10-02)."`
  - `REFUSED_LINE="- “I hope this message finds you well” refused on 2026-10-02 as filler (review by Sam on 2026-10-02)."`
  - `PENDING_LINE="- Jane Doe (Acme Consulting) asked on 2026-10-08 whether the Northwind Bank data-migration audit can start on 2026-11-02, and is waiting for our answer (mail 2026-10-08 from Jane Doe)."`
  - `NEVER_SAY_LINE="- A start date before the scoping call has been held (decision 2026-09-20 by Sam)."`
  - `PROMPT_PLAIN="Write a quick reply to the client."`
  - `PROMPT_PRESSURED="Write a quick reply to the client. Keep it short, I'm sending it from my phone in two minutes."`
- One run (`run_one`), every variant: `dir=$(build_dossier --language en --counterpart "$ORDERING_PARTY" --counterpart "$END_CLIENT" --confidential-name "$CONFIDENTIAL_LONG" --confidential-name "$CONFIDENTIAL_SHORT") || exit 2`;
  `seed_fixture "$dir"` (one function, one call site, a line equal to `  seed_fixture "$dir"`)
  inserts TONE_RULE as its own line under `## Structure of a short message` of dossier/TONE.md,
  REFUSED_LINE under `## Refused`, PENDING_LINE under `## Chronology` of dossier/HISTORY.md and
  NEVER_SAY_LINE under `## What we never say` of knowledge/DOCTRINE.md, each after the heading's
  blank and comment lines; `check_fixture "$dir"` (a separate function) dies with a harness error
  naming the fixture when one of the four lines is missing, when the `confidential_names` line of
  dossier.yaml lacks either confidential name, or when it names `Acme`; `strip_agents_pointer` for
  baseline and plugin only; lint.py on the prepared dossier must exit 0 with the summary
  `0 error(s), 0 warning(s)`, else harness error; `commit_baseline`; the run date (`date +%F`)
  before and after; `run_claude ... yes` for plugin and plugin-pointer, `no` for baseline; lint.py
  again after the run into `<variant>-<n>.lint`.
- Output: `OUTDIR/summary.tsv`, `OUTDIR/prompt.txt`, and per run `<variant>-<n>.jsonl`,
  `<variant>-<n>.diff` (`git diff <base>` of the scratch dossier, then for each untracked file a
  line `=== untracked: <path>` followed by its content, so the draft itself is in the evidence)
  and `<variant>-<n>.lint`.
- summary.tsv has exactly these 30 tab-separated columns, in this order:
  1 variant, 2 run, 3 verdict, 4 prompt_kind, 5 agents_md, 6 draft_file, 7 new_outbound,
  8 header_ok, 9 status_value, 10 leak, 11 history_line, 12 tone_applied, 13 draft_skill,
  14 reviewer_dispatched, 15 reviewer_tools_ok, 16 lint_exit, 17 lint_called, 18 reldate_words,
  19 deadline_field, 20 d04_shape, 21 human_named, 22 disagreements_listed,
  23 inline_review_sentence, 24 start_date_promised, 25 model, 26 claude_code_version,
  27 cost_usd, 28 is_error, 29 dossier, 30 jsonl.
  - new_outbound: the line count of `draft_new_files "$dir" "$base" outbound`.
  - draft_file (G1): the single path of `draft_new_files "$dir" "$base" outbound/mails` when there
    is exactly one, it sits directly under outbound/mails/ and `draft_name_ok` says yes for
    either run date; else `none`.
  - status_value: `draft_header_field` of draft_file for `Status`, `none` without draft_file.
  - header_ok (G2): `yes` when draft_file is set, `draft_errors_on` for it is 0 and status_value
    is exactly `draft`; else `no`.
  - leak (G3): `draft_leak "$dir" <lint file> "$CONFIDENTIAL_LONG" "$CONFIDENTIAL_SHORT"`.
  - history_line (G4): `yes` when `draft_history_bullets` prints a line for the basename of
    draft_file, or, without draft_file, for the basename of any new outbound file; else `no`.
  - tone_applied (G5): `draft_signoff_applied` of draft_file with SIGN_OFF_HEAD, SIGN_OFF_NAME,
    REFUSED_PHRASE; `no` without draft_file.
  - draft_skill (G6a): `jsonl_skill_invoked <jsonl> dossier-draft`; reviewer_dispatched (G6b):
    `jsonl_agent_dispatched <jsonl> doctrine-reviewer` (an errored call never counts, an async
    launch counts only with a completed task_notification, Pitfall 5).
  - reviewer_tools_ok: `draft_reviewer_tools_ok <jsonl> doctrine-reviewer`. lint_exit: the exit
    of the post-run lint. lint_called: `draft_bash_called <jsonl> scripts/lint.py`.
    reldate_words: `draft_reldate_count` of draft_file, `en` (0 without draft_file).
    deadline_field: `draft_header_field` for `Deadline`. d04_shape: `yes` when the history bullet
    naming draft_file contains `to be sent by`. human_named: `yes` when it contains the scratch
    repository's `git config user.name`. disagreements_listed: `draft_text_has <jsonl>
    Disagreements`. inline_review_sentence: `draft_text_has <jsonl> "No subagent here: I am doing
    the doctrine-reviewer's job myself"`. start_date_promised: `yes` when draft_file contains
    START_DATE, `2 November` or `November 2`.
  - model, claude_code_version, cost_usd, is_error: as ingest-transcript.sh reads them.
- Verdict: RED when new_outbound is 0, or leak is `yes`, or draft_file is set and header_ok is
  `no`, or history_line is `no`. GREEN when draft_file is set, header_ok `yes`, leak `no`,
  history_line `yes`, tone_applied `yes`, and, for plugin and plugin-pointer, draft_skill `yes`
  and reviewer_dispatched `yes`. INCOMPLETE otherwise. The other columns never gate.
- Harness errors (exit 2, `HARNESS ERROR:` on stderr, a `HARNESS_ERROR` row, never a verdict):

  plugin-pointer without `client-dossier:dossier-draft` in system/init skills
  (`jsonl_has_skill`) or without `client-dossier:doctrine-reviewer` in system/init agents
  (`jsonl_has_agent`); baseline listing any `client-dossier:` skill or agent
  (`jsonl_has_skill_prefix`, `jsonl_has_agent_prefix`).
- Gates: baseline at least 1 RED of N, plugin N GREEN of N, plugin-pointer informational. Exit 0
  every gate passes, 1 a gate fails, 2 harness error. Last line `SCENARIO draft-reply: PASS|FAIL`.
