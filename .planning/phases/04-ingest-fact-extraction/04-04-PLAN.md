## The skill's command lines (fixed here; SKILL.md carries them verbatim, the guard test reads them)

Every command the skill issues sits alone on one line inside a ```bash fenced block of SKILL.md
(no line continuation, no other kind of line in those blocks except `#` comments). Fact-line
examples and the proposal markup use ```text blocks instead. The lines, with angle-bracket
placeholders the agent fills in:

1. `test -x ${CLAUDE_SKILL_DIR}/scripts/file_source.py`
2. `${CLAUDE_SKILL_DIR}/scripts/file_source.py fetch "<url>"`
3. `${CLAUDE_SKILL_DIR}/scripts/file_source.py --kind <kind> --date <YYYY-MM-DD> --slug "<slug>" "<path>"`
4. `test -x ${CLAUDE_SKILL_DIR}/scripts/extract-text.sh`
5. `${CLAUDE_SKILL_DIR}/scripts/extract-text.sh "<filed pdf>"`
6. `grep -n '^#' dossier/*.md`
7. `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/lint.py`
8. `find sources -type f ! -name .gitkeep -exec shasum -a 256 {} +` (bare-skills route)
9. `shasum -a 256 "<path>"` (bare-skills route)
10. `cp -n "<path>" "sources/<folder>/<YYYY-MM-DD>_<slug><ext>"` (bare-skills route)
11. `[ ! -e "<txt>" ] && pdftotext -enc UTF-8 "<filed pdf>" - > "<txt>"` (bare-skills route)

The placeholder set is exactly `<url>`, `<kind>`, `<YYYY-MM-DD>`, `<slug>`, `<path>`,
`<filed pdf>`, `<folder>`, `<ext>`, `<txt>`. The direct-execution form of lines 2, 3 and 5
matches the skill's `allowed-tools` patterns (a pre-approval convenience only, never a security
control).
