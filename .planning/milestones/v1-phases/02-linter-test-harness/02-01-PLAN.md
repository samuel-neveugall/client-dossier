## Deviation from locked decision D-28

**Status: ARBITRATED 2026-09-17 by the mission manager — DEVIATION ACCEPTED. No human has
settled this; Samuel was offline and this is a harness-fidelity call inside the phase, not a
scope or product change. Rationale: D-28 and D-31 are not jointly satisfiable, and D-31's
stated purpose (producer and linter stay in sync) is the one ROADMAP criterion 1 depends on.
D-28's "readable reference" purpose is carried by the committed `tests/fixtures/lint/fr/` tree
and by a documented header on `make-lint-fixtures.sh`. Samuel can still reverse it with the
scoped edit at the end of this section — that reversal path stays valid and must not be
deleted. `02-CONTEXT.md` D-28 records the same arbitration.** It is recorded here, at
the same visibility as the flagged LINT-03 edge above, because it is a divergence from a
**locked** entry of `02-CONTEXT.md` `<decisions>` — not from "Claude's Discretion" and not from
an assumption awaiting validation. Execution is not blocked by it; a reversal is a scoped edit,
described at the end of this section.

**What D-28 says, literally.** "Fixtures live under `tests/fixtures/lint/`. Two are **committed
static trees**, because they are the readable reference and criteria 1 and 3 assert on them:
`tests/fixtures/lint/clean/` (a full layout with `.gitkeep` in every empty leaf → exit 0, zero
findings) and `tests/fixtures/lint/fr/`." Two committed trees, named.

**What this plan set does instead.** Only `tests/fixtures/lint/fr/` is committed (plan 02-05).
There is **no** `tests/fixtures/lint/clean/` directory anywhere in the six plans. The clean
fixture is materialised at test time by `scratch_repo()` plus a real `init.py` run, inside
`tests/test-lint.sh`, and the error fixtures are copied from that generated tree by
`tests/fixtures/make-lint-fixtures.sh`.

**The measured reason.** `02-RESEARCH.md` § Open Questions Q-7 records the measurement: `init.py`
writes a `.gitkeep` into seven leaves but creates twelve directories, so `sources/transcripts/`
holds only its `raw/` subdirectory and no `.gitkeep` of its own; git tracks no empty directory,
so `git ls-files` after committing a scaffold shows `sources/transcripts/raw/.gitkeep` and no
entry for `sources/transcripts` itself. A committed clean tree is therefore **not** byte-for-byte
what the scaffolder produces, and it drifts further the first time `init.py` gains a template or
a folder. That matters here more than it would elsewhere, because ROADMAP criterion 1 is "a
freshly scaffolded dossier lints clean": asserted against a hand-maintained tree, that criterion
degrades into a tautology about the fixture rather than a statement about the scaffolder.

**The internal tension inside `<decisions>` itself.** D-28 and D-31 sit in the same locked block
and pull opposite ways. D-31: "The planner should build the clean fixture **by running
`init.py`** into the fixture path (or by copying its exact output) rather than hand-writing it,
**so the two stay in sync**." D-31's stated *purpose* — the two stay in sync — is the thing a
committed tree cannot structurally deliver, for the reason measured above. D-28's stated
*purpose* — "the readable reference" — is the thing a generated tree cannot deliver, because
there is nothing to read in the repository. Both decisions are locked; they are not jointly
satisfiable in their literal form, and picking a side silently is exactly the defect this
section exists to stop. Resolving that tension is Samuel's call, not the planner's.

**What the executor does if this deviation is REJECTED.** Do not replan. The reversal is
scoped to plan 02-05 plus two assertions, and it is this shape:

1. Add a task to `02-05-PLAN.md` creating `tests/fixtures/lint/clean/` by running `init.py`
   into that path with `--language en` and committing the resulting tree, plus a `.gitkeep` in
   `sources/transcripts/` so the one directory git would otherwise drop survives a clone. That
   extra `.gitkeep` is an addition to the scaffolder's output and must be commented as such in
   the fixture's README, since it is the precise point where the committed tree and `init.py`
   stop being identical.
2. Add the **drift assertion** `02-RESEARCH.md` Q-7 names, without which the committed tree
   rots silently: generate a fresh scaffold into a scratch repository, take the `find`-sorted
   list of paths relative to each root for both trees, and assert the two lists are equal except
   for the known `sources/transcripts/.gitkeep` addition. A committed fixture with no drift
   assertion is strictly worse than no committed fixture, because it looks like a guarantee.
3. Keep the generated clean tree as well — `tests/test-lint.sh`'s zero-findings acceptance cases
   (plan 02-06, Task 1) and `make-lint-fixtures.sh`'s input stay on the generated tree, so
   criterion 1 keeps asserting something about the scaffolder rather than about the fixture.

Nothing else in the six plans changes under a rejection: no wave moves, no identifier changes,
no acceptance criterion elsewhere is affected.
