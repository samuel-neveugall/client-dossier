## Reading this plan

In the automated verify commands `&amp;` stands for a shell `&`, as in every earlier plan of this phase
(XML escaping). In prose and behaviour blocks, HTML character references are named in words (the
`amp` reference, the decimal `39` reference): write them into the fixture as the literal
reference text — ampersand, name or `#` and digits, semicolon — exactly as 02-REVIEW.md § CR-03's
reproduction block shows them. Format characters are given by code point, with the UTF-8 bytes in
octal for bash 3.2's `printf` (the generator has no `\u`): U+200B `\342\200\213`, U+FEFF
`\357\273\277`, U+00AD `\302\255`, U+200C `\342\200\214`, U+2060 `\342\201\240`.

## Decisions taken in this plan (report them in the SUMMARY under "Decisions for Samuel")

- **D-GAP-4 (reversible):** quote markers are stripped from the E5 haystack in place (the
  stripped text replaces the base) rather than added as a variant: the strip removes only leading
  whitespace and `>` characters that precede a quote, which no name contains, so no match is lost.
  The status-header checks E1-E3 keep reading the raw text.
- **D-GAP-5 (reversible):** HTML references are decoded for every outbound text file, not only
  `.html`: `&amp;`-style text also reaches Markdown and mail drafts pasted from HTML (02-REVIEW.md
  CR-03), and the decoded variant is only built when decoding changes something.
- **D-GAP-6 (reversible):** a format character is read two ways on every side — as nothing (a
  soft hyphen inside `Glo<U+00AD>bex`) and as a word break (a ZWSP between `Contact` and `Acme`) —
  because either reading alone misses a real case. The finding names the space reading of the
  configured name (`'Glo bex'`), which also keeps bidirectional-control characters out of E5
  messages. `init.py` writes the space reading: a soft hyphen inside a word becomes a visible
  space in `dossier.yaml` (cosmetic; the folded pass still matches `Globex`), and that also
  applies to every other quoted field, as D-FIX-12 already does for line breaks.
