## Deviations from the spec

**The deviation.** `skills/dossier-init/scripts/init.py` and
`skills/dossier-init/templates/{en,fr}/` live **inside the skill folder**, not at the
repository-root `templates/` that spec §4's architecture tree currently shows.
`scripts/lint.py` (Phase 2, shared by several skills) is unaffected and still lands at the
repository-root `scripts/`, exactly as spec §4 says.

**Its authority.** Locked decisions **D-05** and **D-06** in
`.planning/phases/01-scaffold-templates/01-CONTEXT.md`, validated by Samuel during
discuss-phase (that document's `Status: Ready for planning`). D-06 states in its own words
that "the spec's architecture tree (§4, `templates/` at the root) is to be amended accordingly
during this phase". `01-RESEARCH.md` confirms the layout is technically sound with two
independent official sources: the Agent Skills open standard documents optional `scripts/`,
`references/` and `assets/` subfolders "plus additional files/directories" inside a skill
folder, and the Claude Code plugin reference shows `scripts/` inside a plugin skill directory
with `${CLAUDE_SKILL_DIR}` as the documented way to address it. Bare-skills installers copy or
symlink the whole skill folder, so the bundled resources survive that install path.

**Its reversibility cost: costly** (as already rated in D-05 and D-06). Undoing it means
rewriting three things in lockstep: the skill prose that names the paths, Phase 2's bash tests
that call the script by path, and the D-07 inline fallback that describes the same procedure.
It is not one-way — no data migration, no published contract, nothing on disk in a user's
dossier records the plugin's internal layout.

**Why no `checkpoint:decision` gates it.** `REVERSIBILITY_GATES` inserts a decision checkpoint
only for `one-way` ratings. D-05/D-06 are `costly`, and they were already put to Samuel and
locked in discuss-phase; a checkpoint here would re-ask a question with a recorded answer and
stall wave 1. The weight is instead made visible where a reader will meet it: this section,
the `<reversibility>` tags on the tasks that implement it, and the two dedicated amendment
tasks in `01-06-PLAN.md` that bring `docs/superpowers/specs/2026-09-16-client-dossier-design.md`
§4 and `CLAUDE.md` into agreement with the code — which is what `CLAUDE.md`'s own precedence
rule ("when this file and the spec disagree, the spec wins and this file must be updated")
requires.

**Naming note (RESEARCH O-1), rated `reversible`.** The Agent Skills standard's canonical name
for a bundled static-resource folder is `assets/`; D-06 locked `templates/`, which the standard
permits as an "additional directory". Kept as decided; renaming a folder is a one-commit undo.

Functions:
`yaml_quote(s)` — returns a double-quoted scalar with `\` and `"` escaped and every character below

`parse_counterpart(spec)` — splits on `|` into name, role, contacts; contacts split on `;`; missing

`render_dossier_yaml(cfg)` — one f-string reproducing spec §3.2's block: the ten keys, in spec

phase only writes the file, and parsing is Phase 2's problem with the tiny YAML-subset parser the
spec already prescribes.
`render_template(text, today)` — replaces the date token only on a line matching
`^(Last updated:[ \t]*)YYYY-MM-DD[ \t]*$` (multiline mode) with the same prefix plus
`datetime.date.today().isoformat()`. Anchoring to that line is required: the same token appears
inside the status-header illustration of a later template and must survive verbatim there.
`under_root(root, path)` — `os.path.commonpath([root, os.path.realpath(path)]) == root`; every write
target is checked with it and a failure exits non-zero with a message on stderr, having written
nothing.
`write_if_missing(path, text)` — returns `"created"` after creating parent directories and writing,
or `"kept"` when the path already exists. It never opens a file for writing when the path exists —
no truncation, no overwrite, no "merge". This is D-08 and it is the single control that stops a
re-run from destroying a living dossier.
`main(argv)` — resolves the target root, creates `FOLDERS`, writes the seven `.gitkeep` files
(empty), writes `dossier.yaml`, then walks `TEMPLATE_MAP` reading each template from
`Path(__file__).resolve().parent.parent / "templates" / <variant>` and writing the rendered text.
It prints one line per path, `created: <path relative to the target root>` or `kept: <path>`, then
a one-line summary, and returns 0. Locating the bundled templates from `__file__` is correct here
and is the one place path arithmetic is right — the script is finding its own sibling directory,
not the plugin root, which is what `${CLAUDE_SKILL_DIR}` is for from `SKILL.md`.

Never build a shell command string anywhere in this script, now or later: any subprocess call uses
an argument list with `shell=False`. No path component is derived from user input in this phase —
every path is a fixed English constant (CLAUDE.md C-3), and keeping it that way is what makes
traversal unreachable rather than merely guarded.
