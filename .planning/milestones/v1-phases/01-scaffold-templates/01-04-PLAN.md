    - Target absent → the file is created containing the start marker, the body, the end marker, and nothing else.
    - Target exists without the markers → the block is appended after the existing content, separated by one blank line; every pre-existing byte is preserved.
    - Target exists with exactly one marker pair → only the span between the markers is replaced; the text before the start marker and after the end marker is preserved byte for byte.
    - Two identical consecutive runs → the second changes no byte in either file.
    - `CLAUDE.md` absent → nothing is created and the report says the target was skipped.
    - Target exists with a start marker and no end marker → the script exits non-zero with a message naming the file, and writes nothing to it; a half-marked file is ambiguous and guessing could delete a person's instructions.

  <files>skills/dossier-init/scripts/init.py</files>
  <action>
Add `upsert_marker_section(path, body)` and wire it in. Standard library only, Python 3.8-safe.

Module-level constants `MARKER_START = "<!-- client-dossier:start -->"` and
`MARKER_END = "<!-- client-dossier:end -->"`, so both the script and any future reader see the
exact strings in one place.

`upsert_marker_section(path, body)` returns one of `"created"`, `"appended"`, `"updated"` or
`"unchanged"`:
- read the file when it exists, treating it as UTF-8;
- count occurrences of each marker. Zero of each → append `"\n" + block` to the existing content,
  or write `block` alone when the file did not exist. Exactly one of each, start before end →
  splice the new block over the span from the start marker through the end marker inclusive. Any
  other count, or an end marker before a start marker → raise, so `main` exits non-zero with a
  message naming the file, having written nothing to it;
- if the resulting text equals the existing text, do not rewrite the file and return
  `"unchanged"` — this is what makes the `diff -r` assertion in the re-run case hold;
- `block` is `MARKER_START + "\n" + body.strip() + "\n" + MARKER_END + "\n"`.

This function is the **only** write path in `init.py` that does not go through
`write_if_missing`, and that is deliberate: here the file exists but the section may not, so
skip-if-the-file-exists would silently do nothing (RESEARCH Pitfall 7). Every other target in the
script keeps D-08's rule untouched.

Wire it into `main`, after the templates are written:
- read the body from `resolve_template_dir(...) / "AGENTS-pointer.md"`, passed through
  `render_template` like any other template;
- always call it on `<target>/AGENTS.md`;
- call it on `<target>/CLAUDE.md` **only when that file already exists**; when it does not, write
  nothing and report it as skipped (D-16);
- both paths go through the existing `under_root()` guard;
- print one report line per target: `pointer: <created|appended|updated|unchanged> AGENTS.md` and
  the matching line for `CLAUDE.md`, or `pointer: skipped CLAUDE.md (absent)`.

`AGENTS-pointer.md` stays out of `TEMPLATE_MAP` — it has no scaffold target of its own and is
consumed only here.
