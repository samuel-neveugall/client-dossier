## README outline (fixed here; headings exact, order exact)

Decision ids in this outline are for traceability; the README itself cites none.

1. `# client-dossier`, then one paragraph from spec §1: what the plugin does (a git repository becomes
   the memory of a relationship with an external party), and that it never sends anything and never
   renders documents.
2. `## What it is`: the four regimes (immutable `sources/`, the living `dossier/` where every fact
   line is dated and sourced, `knowledge/`, `outbound/` where only a human sends a reviewed draft);
   skills carry judgement, scripts mechanics, hooks reminders.
3. `## The dossier layout`: the tree `dossier.yaml  sources/  dossier/  knowledge/  outbound/`
   (fixed English names, never configurable) and the protocol keywords quoted untranslated
   (`Last updated:`, `Status:`, `To:`, `Subject:`, `Deadline:`, `Written by:`, `Rules:`, `draft`,
   `reviewed by`, `sent`), whatever the dossier's language.
4. `## Installation`, with four subsections:
   - `### Claude Code`: `/plugin marketplace add samuel-neveugall/client-dossier` then
     `/plugin install client-dossier@client-dossier`; shell equivalents
     `claude plugin marketplace add samuel-neveugall/client-dossier` and
     `claude plugin install client-dossier@client-dossier`; pinning a release with
     `claude plugin marketplace add samuel-neveugall/client-dossier@v1.0.0` once that tag exists;
     a local clone path works too.
   - `### Codex`: `codex plugin marketplace add samuel-neveugall/client-dossier` (add `--ref v1.0.0` to
     pin a release) then `codex plugin add client-dossier@client-dossier`; Codex runs the plugin's
     hooks only after you trust them in `/hooks`; the two agents are not used on Codex (its custom
     agents are not plugin-bundled), the skills run their inline procedure instead; file edits through
     `apply_patch` are guarded like Claude Code's Write family; OpenAI's public plugin directory does
     not list plugins with lifecycle hooks, so this plugin is installed from its own marketplace.
   - `### Agent Skills harnesses (Cursor, Copilot CLI, Gemini CLI, OpenCode)`:
     `npx skills add samuel-neveugall/client-dossier` (the tested CLI version is skills@1.7.2:
     `npx skills@1.7.2 add samuel-neveugall/client-dossier`), or copy each folder of `skills/` into
     the harness's skills folder. Then a paragraph `What this install loses`: `scripts/lint.py` (the
     skills state the linter's rules and check them by reading), the three hooks (the `dossier` skill
     states every rule they enforce), the two agents `fact-extractor` and `doctrine-reviewer` (the
     skills run the extraction and the review inline); outside Claude Code `${CLAUDE_SKILL_DIR}` is
     not replaced, so the private scripts copied with each skill are treated as absent and the stated
     fallback runs.
   - `### Without a plugin (AGENTS.md only)`: `dossier-init` writes a pointer into the repository's
     `AGENTS.md` (or `CLAUDE.md`); any harness that reads it follows the protocol.
5. `## Usage`: the five task skills are slash commands in Claude Code (`/client-dossier:dossier-init`,
   `/client-dossier:dossier-ingest`, `/client-dossier:dossier-draft`, `/client-dossier:dossier-call`,
   `/client-dossier:dossier-status`, arguments passed through), and they trigger on plain requests;
   the `dossier` skill loads itself in a dossier (SessionStart reminder); `python3 scripts/lint.py [PATH]`
   from a clone, with its exit codes (0 no error, 1 at least one error, 2 no `dossier.yaml` found
   upward or unreadable, 3 internal error). The section ends with its last paragraph; plan 07-08
   appends `### Commands` after it.
6. `## Limits`, with `### The sources guard` (03 D-04, 03 D-17: what it denies and what it does not
   see, verbatim classes as in the truths; "the skill's rule is the real boundary"; Codex apply_patch
   covered) and `### Confidential names` (05 D-09: abbreviations, acronyms, nicknames, translations,
   homoglyphs outside a small table are not caught by `scripts/lint.py`; the `doctrine-reviewer` is
   the only net).
7. `## Requirements`: python3 3.8 or newer, git; optional `pdftotext` (missing: the PDF is filed and
   extraction is reported as skipped).
8. `## Versioning`: semantic versioning, `CHANGELOG.md` (Keep a Changelog), one git tag `vX.Y.Z` per
   release, both manifests always at the same version, `scripts/release.sh <version>` bumps them, adds
   the changelog heading and creates the tag locally; it never pushes.
9. `## License`: MIT, Copyright (c) 2026 Samuel Neveu, see [LICENSE](LICENSE).
10. `## Privacy`: the plugin never sends anything; everything stays in your git repository; a
    local-path install copies the working tree as it is, so install from GitHub or a clean clone.
